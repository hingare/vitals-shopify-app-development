# দোকানের উইজেটের পরীক্ষা (Playwright)

`packages/widgets/e2e` একটা নকল Shopify দোকান বানায় (Dawn-এর মতো পাতা, Shopify-র Ajax API আর আমাদের App
Proxy-র নকল উত্তর) আর আসল বিল্ড করা উইজেট (`theme-embed/assets`) চালায়। ইন্টারনেট বা কোনো দোকান লাগে না।
প্রতি PR-এ CI-র `storefront` ধাপে ডেস্কটপ (1280×800) আর ফোনে (Pixel 7) চলে।

## কী দেখে

- **প্রতিটা টুল একা চালু করে** (`tools.e2e.ts`): টুলটা আসলেই দেখা যায়, axe-core-এ (WCAG 2.2 AA আর ভালো অভ্যাস)
  serious বা critical সমস্যা নেই, জাভাস্ক্রিপ্ট ভুল নেই, আর পাতা ০.০১-এর বেশি সরে না (CLS)। moderate আর minor
  সমস্যা ব্যর্থ করে না, রিপোর্টে থাকে। টুল চালুর আগের নকল পাতাটা নিজে পুরো পরিষ্কার, তাই যা ধরা পড়ে তা টুলেরই।
- **কীবোর্ড** (`keyboard.e2e.ts`): পপ-আপ, স্পিন হুইল, সাইজ চার্ট, উইশলিস্ট, কার্ট ড্রয়ার, সার্চ, চ্যাট, কুইক লিংক আর
  আপসেল খুললে ফোকাস ভেতরে যায়, Tab পেছনের পাতায় যায় না, Escape বন্ধ করে আর ফোকাস আগের জায়গায় ফেরে; খোলা
  অবস্থায়ও axe চলে। ট্যাব, Agree to terms, Back in stock আর রিভিউ ফর্ম কীবোর্ডে পুরো চলে কিনা।

## চালানো

```sh
pnpm --filter @app/widgets build
pnpm --filter @app/widgets e2e              # সব
pnpm --filter @app/widgets e2e -g popup     # নামে "popup" আছে এমন পরীক্ষা
```

প্রথমবার নিজের PC-তে: `pnpm --filter @app/widgets exec playwright install chromium`। ব্যর্থ হলে
`packages/widgets/test-results`-এ পাতার স্ক্রিনশট আর অবস্থা থাকে (CI-তে artifact হিসেবে)।

## নতুন টুল যোগ করলে

`e2e/scenarios.ts`-এ টুলের ঘর লাগবে: কোন পাতায়, কোন সেটিংসে দেখা যায়, আর দেখা গেলে কোন উপাদান থাকে। না দিলে
"every storefront tool has a scenario" পরীক্ষা ব্যর্থ হয়। ভুল সেটিংস দিলে (যা টুল মানে না) পরীক্ষা সাথে সাথে বলে।

## পাতা সরে না: আগেভাগে বসা উইজেট

যে টুলগুলো পাতার ভেতরে কিছু বসায়, সেগুলো পাতা আঁকার আগেই বসে, তাই পরে লেখা নিচে সরে না: Announcement bar আর
Spending goal (উপরে), Countdown timer, Volume discounts, Bundles, Upsells (Add to cart-এর নিচে), Cart notice আর
Agree to terms (কার্ট পেজে), Description tabs।

- app embed পাতার `<head>`-এ বসে (`target: head`)। এই টুলগুলোর কোনোটা চালু থাকলে embed `snippets/app-early.liquid`
  বসায়: `packages/widgets/src/early.ts` থেকে বানানো ছোট inline স্ক্রিপ্ট।
- স্ক্রিপ্টটা থিমের HTML পড়ার সময় চলে (MutationObserver, যার ডাক ব্রাউজার পাতা আঁকার আগে আসে)। থিমের যে জিনিসের পাশে
  উইজেট বসবে (Add to cart ফর্ম, চেকআউট বাটনের ঘর, বিবরণ) সেটা পুরো পড়া হলেই উইজেট বসায়; আগে নয়, কারণ তাহলে থিমের
  বাকি HTML ভেতরে যোগ হয়ে উইজেটকে নিচে ঠেলে দিত। মার্চেন্টের app block থাকলে উইজেট সেখানে যায়।
- Bundles আর Upsells-এর প্রোডাক্ট পরে আসে, তাই তাদের শুধু ঠিক ততটা জায়গা রাখা হয়। এজন্য তাদের বাক্সের মাপ বাঁধা
  (`src/early/reserve.ts`): মাপ বদলালে সেখানকার হিসাবও বদলাতে হয়, না হলে এই পরীক্ষা ব্যর্থ হয়।
- টুলের নিজের ফাইল পরে এসে বাকিটা চালু করে (মেসেজ ঘোরানো, কার্ট বদলালে লেখা, গোনা)। স্ক্রিপ্ট না চললে টুলের ফাইল আগের
  মতো নিজেই উইজেট বসায়।
- স্নিপেটটা git-এ থাকে; হাতে বদলাবেন না। `early.ts` বা `src/early/` বদলালে `pnpm --filter @app/widgets build` চালিয়ে
  স্নিপেটসহ commit করুন। `pnpm test` মিলিয়ে দেখে, পুরনো থাকলে ব্যর্থ হয়।
- স্ক্রিপ্টটা Shopify-র ১০০KB Liquid সীমায় গোনা হয় (`apps/admin/app/lib/theme-extension.test.ts` দেখে)। এখন সব Liquid
  মিলিয়ে প্রায় ৯৬KB, তাই এখানে নতুন কিছু যোগ করার আগে মাপ দেখুন।

পরীক্ষা: প্রতিটা টুলের সাধারণ পরীক্ষা ছাড়াও `"<টুল> while the page is still arriving"` পাতাটা ধীরে আনে (`slow`
অপশন: `<body>`-এর শুরু, ফর্মের মাঝখান, বিবরণের মাঝখান আর চেকআউট বাটনের পরে থিমের একটা ধীর স্ক্রিপ্ট), যাতে ব্রাউজার
HTML পড়ার মাঝেই কয়েকবার পাতা আঁকে, যেমনটা ধীর ফোনে হয়। টুলের তালিকা embed-এর Liquid থেকেই নেওয়া। নতুন টুল পাতার
ভেতরে কিছু বসালে তাকেও এখানে যোগ করুন: embed-এর `case` তালিকা, `early.ts` আর টুলের ফাইলে `adopt()`।
